Build Elon Reply Agent — Vercel v0 Production Application

Build a complete, production-ready X (Twitter) AI assistant called Elon Reply Agent.

IMPORTANT: Build using the existing v0 project. Inspect existing files and preserve working components.

TECH STACK

* Next.js App Router
* TypeScript
* Tailwind CSS
* shadcn/ui
* Supabase PostgreSQL
* OpenRouter API
* Groq API fallback
* Official X API v2
* OAuth 2.0 Authorization Code with PKCE
* Vercel deployment
* Vercel Cron Jobs

DESIGN

Create a premium Grok-inspired dashboard:

* Pure black background (#000000)
* White text
* Inter font
* Minimal blue accents
* Responsive mobile and desktop layouts
* Bottom navigation on mobile
* Sidebar on desktop

MAIN FEATURES

1. Dashboard

Display:

* Connected X account
* Total followers
* Following count
* New notifications
* Pending AI replies
* Published posts
* Engagement statistics
* API spending

2. X OAuth

Implement secure OAuth 2.0 PKCE.
Allow users to connect, disconnect and reconnect their X accounts.
Store encrypted tokens securely.
Use only official X APIs.

3. Notification Monitor

Create a protected Vercel Cron endpoint running every five minutes.

Monitor supported mentions and replies using official X API endpoints.
Store new activity in Supabase.
Prevent duplicates.
Handle rate limits and expired credentials.
Display the last synchronization time.

Do not claim to retrieve the entire native X notification feed when the API does not expose it.

4. AI Reply Assistant

Use OpenRouter as the primary AI provider and Groq as fallback.

Analyze post content and available conversation context.

Generate:

* Intelligent replies
* Short conversational replies
* Analytical replies
* Alternative viewpoints

Default style: Intelligent, natural, authoritative and concise.

Provide:

* Generate
* Regenerate
* Edit
* Copy
* Approve
* Reject

All AI replies must remain drafts until manually approved.

Do not activate autonomous AI-powered replies unless the required written X approval has been obtained.

5. Post Management

Allow:

* Drafting posts
* Editing posts
* Previewing posts
* Scheduling posts
* Publishing after explicit confirmation
* Viewing published posts

6. Engagement Management

Display follower growth, likes received, reposts, replies and available impressions.

Follower and following lists should use authorized API endpoints.

Keep liking, following and unfollowing manual. Do not automate prohibited engagement actions.

7. Analytics

Create interactive charts for:

* Daily follower growth
* Weekly engagement
* Monthly performance
* Best-performing posts
* Posting activity

Only display metrics supported by available API data.

8. Supabase

Create tables for:

* profiles
* connected_accounts
* notifications
* monitored_posts
* reply_drafts
* scheduled_posts
* published_posts
* engagement_metrics
* follower_snapshots
* api_usage_logs
* user_preferences

Implement database migrations, indexes and Row Level Security.

9. API Cost Controls

Track X API usage.
Display estimated API spending.
Add configurable usage limits.
Cache results.
Avoid unnecessary polling.
Stop requests when the configured budget is exhausted.

10. Vercel Configuration

Create:

* app/api/x/auth/route.ts
* app/api/x/callback/route.ts
* app/api/x/mentions/route.ts
* app/api/ai/generate/route.ts
* app/api/x/publish/route.ts
* app/api/cron/monitor/route.ts
* app/api/analytics/route.ts

Configure vercel.json with a five-minute cron schedule where supported by the Vercel plan.

Protect all cron endpoints using CRON_SECRET.

Use server-side API calls only.

Create .env.example:

X_CLIENT_SECRET=
X_CALLBACK_URL=
OPENROUTER_API_KEY=
